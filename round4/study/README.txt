能智核 真人价值对照邀测包

当前状态：可运行的软件与任务准备完成；真人实验待实施。
已参与人数：0。独立参考答案复核：待完成。没有专家审核结论或人工提效成绩。

一、直接打开与演练
在 round4 目录执行 python -X utf8 study_server.py --port 18196，浏览器打开 http://127.0.0.1:18196。
参与者在团队安排的电脑上用浏览器即可操作，无需安装客户端；主持机器需要与工作台相同的Python依赖。
“演练A/B”只使用不属于正式八题的既有开发示例，不创建真人记录。正式入口未达到复核条件会拒绝开启。

二、招募前必须完成
1. 邀请一位未参与本系统规则编写的复核者。由团队核实独立性；本包不虚构专家资历。
2. 阅读 private/protocol.json、task_manifest.json、answer_key_draft.json、rubric.json，逐题核对原始CSV/JSON、允许点位与LBNL原始说明。
3. 参考答案中的独立原始统计由单独脚本从原始行计算，没有使用诊断器输出充当真值。候选结论仍是待复核草案。
4. 复核者逐题确认有效时段、可接受结论和替代答案，必要时修改草案；检查配对难度是否合理。真值标签不能迫使不可辨识的观测输出故障。
5. 实际逐题复核完成后，将 answer_key_draft.json 中每题的 review_status 改为 approved，并将 admin/independent_review.json 的 status 改为 approved，填写复核者化名、独立声明、UTC日期、全部8个task_id、各项检查和实质意见，最后更新四份参考文件SHA256。只由实际复核者签署。修改任何参考后必须重新复核签署。软件不会代为完成签署。
6. 签署锁定后才由团队招募5—10名真实人员。这个人数是计划，非已完成或统计功效保证。记录角色及经验档，不收真实姓名、电话或单位。

三、统一主持流程
说明目的、匿名记录和自愿退出。两种条件各用2分钟相同操作介绍，再用培训示例熟悉界面。不要提前显示正式题答案。
系统按加入顺序循环分配S1—S4。每人两阶段各4题，每题上限5分钟，阶段间休息3分钟。
任务对采用第二轮开发集最早两个日期2018-05-07、05-08及四种源设置，未按系统成功与否挑选。
一人每个原始日工况只看一次。顺序同时平衡条件先后、日期版本和题序。记录天气/时长差异，不假定配对难度完全相等。
A给曲线、原始表、单位、正常参考表和相同检查清单；B增加真实工作台计算及核查卡。全程不用外部模型或答案提示。
刷新不应用于重开计时；服务器重启造成的未完成任务须如实记录为中断，不能删去后仅报告成功任务。退测按团队告知与数据政策处理。

四、记录与评分
正式记录保存在 results/participants。参考答案和私有标签不由HTTP接口发给参与者。
记录从任务首次打开至提交的服务器时间，另记后台切换、核验、修正操作；不把程序耗时当人用时。
独立评分者用 admin/scoring_template.csv 对六项关键证据0/1评分，记录错误归因、评分理由及批准答案哈希，保存 results/manual_scores.csv。
超时、未提交或关键错误归因是失败，同时分列各项。无法完成也要提交现有记录；缺题按300秒及失败计入，未决且补证合理不能自动判错。
优先在不知A/B条件的情况下评分答卷，无法完全盲化时如实说明。建议第二人复核分歧，保留原评分及修改原因。
执行 python scripts/analyze_study.py，先按每位参与者汇总A/B再计算配对差值，同时查看遗漏、误归因与失败。
小样本只作探索性描述，不把8个任务当8名独立用户；没有合格真人答卷和独立评分时脚本保持待实施/待评分，不生成提效数字。
