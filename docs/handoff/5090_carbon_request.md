## 0. 原则

1. 所有碳指标都在后端用 Python 计算，写进 report 和回放 JSON；前端只读取显示，不做任何乘法。
2. 每个数字可追溯：排放因子要有官方文件标题、发布单位、数据年份、公告号和链接；用户情景参数（碳价）要写明是情景。
3. 不夸大：
   - 这是基于电网平均排放因子的情景估算，不是经核证的减排量；
   - 不包含光伏、风机制造、运输、回收的隐含排放；
   - 碳收益只是“如果按某个价格出售”的情景值。2 kWp 量级的小项目能否进入 CCER 或地方碳普惠，取决于方法学和备案，**本作品未核实**，页面会这样写。
4. 只有“当时用上”的自发电才替代了电网电；浪费的电不计减碳。卖给电网的电（`allow_export=true` 时）单独列出，不并入自用减碳。

## 2. 每个方案新增的碳字段

在 hybrid（以及 PV，如方便）report 的 `candidates[i]` 下新增 `carbon` 对象；在 report 顶层新增 `carbon_context`。按你们现有生命周期逻辑逐年计算（含光伏衰减，口径与费用一致），并同时给出第 1 年值。

`carbon_context`：

`candidates[i].carbon`：

| 字段 | 定义 |
| --- | --- |
| `grid_emissions_kgco2_year1` | 第 1 年从电网购电 × 因子（S0 即空调全年用电对应排放） |
| `avoided_kgco2_year1` | (S0 购电 − 本方案购电) × 因子（应等于自用电量 × 因子，请做守恒检查） |
| `avoided_tco2_study_period` | 研究期内累计减碳（逐年，含衰减） |
| `curtailed_kwh_year1`、`curtailed_share` | 浪费电量及占发电比例（直接来自匹配结果，方便页面讲“浪费不减碳”） |
| `exported_kwh_year1`、`export_avoided_kgco2_year1` | 外送电量及按同一因子估算的外送替代量，单独列示，不并入 `avoided_*` |

## 3. “年度粗算”对照（创新点页面要用）

为每个方案再算一组常见的“年度抵扣”粗算结果，放在 `candidates[i].annual_offset_estimate`：

- `covered_kwh = min(年发电量, 年空调用电)`；`claimed_coverage_rate = covered_kwh / 年用电`；
- `claimed_avoided_kgco2 = covered_kwh × 因子`；`claimed_bill_saving_cny_year1 = covered_kwh × 电价`（分时电价时用 S0 年电费 / 年用电 的平均电价，并写明）；
- 用与正式结果相同的研究期、折现和设备费用，算 `claimed_incremental_npv_vs_s0_cny`；
- `method = "annual net offset; ignores hourly timing; for comparison only"`。

页面会把它与逐小时结果并排，说明粗算会把“浪费的电”也算成省钱和减碳。粗算只用于对照，不参与推荐。

### 15.1 多余电量的两条去路：储能（为主）+ 卖给电网（粗算）

用户决定（2026-10-07）：不大改项目；对每个发电方案的“多余电量”给出两条简单去路，各算**投入和收益**即可。四个方案的结果、推荐逻辑、主表数字一律不变，这两条去路只作为附加卡片。两条去路**各自独立**从同一份逐时多余电量算起（不做“存还是卖”的优化取舍），页面并列展示，用户自己比较。

**A. 储能（为主，简单计算）**——在现有 `ideal_storage_upper_bound` 上补经济字段：
1. 调度沿用现有简单规则：只用多余的自发电充电，缺电时放电；容量、功率上限、往返效率 0.90；不从电网充电，不做峰谷套利，不用优化求解器。`allow_export=true` 时也照常计算（不再返回 not_applicable），因为两条去路独立计算。
2. 报价输入 `storage.quote`（可选；缺任一项则该容量 `economics_status=incomplete`、金额 `null`，不补默认值）：电池及变流器 `cny_per_kwh`、安装 `installation_cny`、年运维 `maintenance_cny_per_year`、寿命 `life_years`。
3. 每个容量返回：第 1 年放电量（挽回电量）、少买的电费（按放电那一小时的分时电价）、年净收益（减运维）、初始投入、简单回本年限（年净收益 ≤0 或回本年限超过寿命时为 `null` 并写原因）、研究期内净收益（含寿命到期更换，与主方案同一研究期；不折现也可，但须写明口径）、自给率由多少提高到多少。
4. 标出“最划算容量”（含 0 = 不装）；都不划算时写“按当前报价不建议装储能”。
5. 示例：三档各给一份带储能报价的结果，报价写明来源与日期，或标注“示例报价，仅用于演示”。

**B. 卖给电网（粗算）**
1. 输入：上网电价 `export.price_cny_per_kwh`（用户填写；`options` 给一个参考值及来源，例如广东燃煤发电基准价，请 5090 核实数值与文件出处后再写入，核实不了就只留输入框不给参考值）、可选一次性并网/计量投入 `export.connection_cny`（未填按 0 并写明）。
2. 计算：年卖电量 = 不加储能时全年多余电量（即当前的弃电量合计）；年收入 = 年卖电量 × 上网电价；研究期收入、回本年限（有并网投入时）。
3. 文字：说明这是粗算——能否并网、上网电价与结算方式以当地电网批复为准；不考虑上网容量限制以外的政策细节。

**共同要求**
- 响应字段建议：每个发电方案下 `surplus_paths: {surplus_kwh_year1, storage: {...candidates}, export: {...}}`。
- 测试：储能能量守恒（充入×效率 = 放出 + 期末电量变化）；容量 0 时收益为 0；缺报价为 incomplete；卖电收入 = 多余电量 × 电价。
- 中文说明随结果返回：简单规则、不含电池衰减与温度影响、不含峰谷套利、报价与电价由用户填写。
