### 2.2 “多余电量去哪儿”卡片（替换原“储能理想上限”区块）

位置：结果第 3 步，原 `storageBlock` 处。数据：当前选中方案（默认推荐方案；可切换光伏/风机/组合）的 `surplus_paths`。标题：“多余的电去哪儿？”，副标题读 `surplus_kwh_year1`：“这个方案每年约有 X 度电自己用不完”。

左右两栏（手机上下排列），左边为主：

- **左：存起来（储能）**
  - 容量列表（读 `storage.candidates`，含 0 = 不装）：每行显示容量、初始投入、每年少交的电费、每年净收益（扣运维）、几年回本（`null` 时显示原因文字）、10 年净收益、自给率从多少提高到多少。
  - 高亮 `recommended_capacity_kwh` 一行，标“最划算”；为 0 时显示后端的 `recommendation_note`（如“按当前报价不建议装储能”）。
  - 小图：横轴容量，纵轴 10 年净收益（正负分色，0 线清晰）。
  - 注明：“简单规则：多余电先充进电池、缺电时放出；不含电池衰减和温度影响，不做峰谷套利；10 年净收益不折现。”以及“只计算空调用电：下班后和周末楼里不用电，电池晚上没处放，所以容量越大不一定越划算。”
  - 某容量 `economics_status=incomplete` 时显示“条件不全：请填写储能报价”，不显示金额。
- **右：卖给电网（粗算）**

### 2.3 一句话输入接本地大模型（契约见需求文档第 18 节）

- 启动时请求 `GET /api/operation/agent/status`。可用时，“一句话描述”输入框旁显示小标签“本地大模型理解”；不可用、接口不存在（404）或超时，显示“规则识别”并沿用现有本地规则（`form.js` 第 240 行起），行为与第一轮一致。
- 可用时，用户输入后点“理解”：请求 `POST /api/operation/agent/parse`，带上当前表单构造出的请求体。显示等待状态（不显示假进度）。
  - `ok`：弹出“我理解到的修改”列表（中文字段名、原值 → 新值），以及 `unsupported` 里“没能处理”的内容；按钮“采用这些修改”/“取消”。采用后写入表单，被改动的字段高亮 3 秒，结果按现有规则置灰失效；**不自动开始计算**，用户再点“计算”走原有预览 + 全年任务流程。
  - `needs_clarification`：在输入框下显示模型的追问。
  - `unavailable` / `failed` / 超时：提示“本地大模型暂不可用，已改用规则识别”，并用规则识别同一句话。
- 不允许把模型返回的任何内容当作计算结果显示；模型只负责改表单条件。
- 关于页新增一小节“大模型在这里做什么”：理解用户的话 → 提出表单修改 → 用户确认 → 所有数字仍由计算服务算出；本地运行，不上传数据。
- 验收脚本里用一个**仅测试用**的本地桩服务（脚本内启动，不提交到 `operation_planning/`）模拟 status/parse 的四种返回，覆盖上述分支。真实模型的联调由 5090 在本机完成。

### 2.4 第 2、3 步的三句结论

在第 3 步顶部现有一句话结论下面，加一行三个数字卡（数字全部读结果字段，缺失时显示“—”及原因）：

- “空调用电有多少是自己发的”：推荐方案 `load_coverage_rate`；
- “一开始要投入多少”：推荐方案初始投入（`capex_cny`）；
- “大概几年回本”：推荐方案 `simple_payback_years`（`null` 时写“按当前条件不回本”或“只用电网，无需投入”）；小字“简单回本：初始投入 ÷ 每年净节省，不折现，仅供参考”。

第 2 步在台数输入旁加一句小字说明（文字固定，可放在“？”提示里）：“达标判据：允许上班前预冷 1 小时（预冷用电已计入），只在使用时段检查冷量是否够用。冷量够用后再加台数，模型里年用电基本不变（未计入低负荷时的效率变化）。”

### 2.6 电价：自定义分时电价与年涨幅

- **自定义分时电价**（后端已支持，`pv.tariff_id = "custom_user"` + `pv.custom_tariff`，格式见 `operation_planning/tariffs.py` 的 `custom_profile`）：第 1 步电价分组的档案选择中增加“自定义分时电价”。选中后显示四个价格输入（谷 / 平 / 峰 / 尖峰，元/kWh），默认填入当前所选官方档案的四个价格供修改；时段沿用官方时段（谷 0–8 点，峰 10–12、14–19 点，其余平段；尖峰按官方规则），界面只读显示时段说明。结果与简报中标注“用户自定义电价（未经官方核验）”。
- **电价年涨幅**（契约见需求文档第 19 节，字段 `hybrid.tariff_escalation_rate`）：电价分组加一个输入“未来电价每年变化”（%，默认 0，范围 −5～10）。结果第 3 步在 10 年总账附近显示一张小表，读 `escalation_sensitivity`：电价每年 −2% / 0 / +2% / +4% 时，推荐方案与只用电网的 10 年总花费、差额（`incremental_npv_vs_s0_cny`，正数 = 比只用电网省，与候选层同号）、回本年份（读 `cumulative_payback_year`，按逐年累计节省计算；`simple_payback_years` 是按第 1 年节省的简单回本，只放在说明里）；推荐方案就是“只用电网”时不显示该表，改为一句“推荐只用电网，无需投入”；标题“电价变了，结论还成立吗？”，注明“等比调整，不是电价预测”。字段缺失时不显示该表。
- 一句话输入示例补充：“电价每年涨 3%”→ 修改年涨幅（模型或规则识别均可）。本地模型现可识别的字段见 `operation_planning/agent_parse.py` 的 `FIELD_RULES`（含年涨幅、风机台数、储能单价与可选容量），修改清单里的字段名按这里显示为中文。
