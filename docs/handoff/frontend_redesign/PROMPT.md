## 3. 产品定位与文案

- **品牌名**：能见度（暂定，正式申报前用户会做商标检索；仓库名、包名、接口、字段 ID 不改）。
- **定位**：低碳改造决策助手。
- **主标题**：看见每一小时的电。副标题：再决定花不花这笔钱。
- **要解决的实际问题**：学校后勤、物业、园区、厂房管理者在推进低碳改造时，常被推荐加装光伏、小风机。花钱之前，系统按当地全年 8,784 个小时的天气回答四个问题：
  1. 空调配几台才够用？（台数比选）
  2. 发的电当时用得上吗？（逐小时匹配，浪费的电不算省钱、不算减碳）
  3. 装不装、装多大最划算？（四种供电方式 + 光伏容量比选，10 年总账）
  4. 真实减了多少碳、每吨减碳多花或省下多少钱？
- **三个核心故事**（来自 5090 真实数据，页面直接用数据讲，数字从文件/接口读取）：
  - **装多大比装不装更关键**：小档办公室装 1 kWp 能省钱，装 2 kWp 反而多花（容量比选曲线）。
  - **使用时段决定能用上多少电**：每天开放的图书馆，光伏自用率明显高于只在工作日用电的办公室。
  - **两种算法结论相反**：常见的“年发电抵年用电”粗算（`annual_offset_estimate`）会把浪费的电也算成省钱；逐小时结果可能相反。
- 主界面用通俗中文，技术名（pvlib、SD6、Hellman、NPV、S0–S3、字段名）只出现在“依据”抽屉或“关于数据与边界”页。

### 4.1 首页（叙事页，按确认稿）

自上而下：
1. **首屏**：左侧主标题、一句说明、两个按钮（一键演示 / 开始试算）；右侧 **3D 微缩场景**（办公楼或厂房、屋顶光伏、小风机、树木、阴影），由真实逐小时数据驱动：太阳光强随当时光伏发电、窗户在空调用电时亮起、风机转速随风电、能量粒子青色飞进房间=用上、橙色飘走=浪费；HUD 显示当前日期时刻和这一小时的用电/发电/用上/浪费数值。默认用示例中某一档的典型周数据（`replay_previews_v7.json`），用户完成一次计算后，首页场景改用该结果的典型周数据。
2. **一个被忽略的事实**：三个大数字（年发电、年用电、浪费的电），进入视野时数字滚动到真实值（≤ 0.9 秒，只对已读取的结果做）。
3. **全年能源日历**（深色区块）：366 天 × 24 小时，三种视图（空调用电 / 光伏与风机发电 / 发电时空调在用吗），可自动轮播、切换时颜色从左到右刷新，悬停显示该小时数值。
4. **电去哪了**：环形图 + 三行数值（用上 / 浪费 / 仍需从电网买），可切换方案。
5. **两种算法**：粗算 vs 逐小时并排，结论相反时突出显示；数据取自 `annual_offset_estimate` 与正式结果。
6. **装多大最划算**：光伏容量比选曲线（`pv_capacity_sweep`），标出最划算容量。
7. **10 年总账**：四种供电方式价格表（只用电网永远在第一列），推荐列高亮，每列写“多花／省下 X 元”。
8. **三档示例入口**：小／中／大三张卡（名称、关键数字、结论），点进去载入工具。
9. **一键演示入口** + 页脚（数据来源、边界、匿名）。

首页所有数字都来自当前选中的示例或用户最近一次计算结果，并标明来源。

### 4.2 开始试算（核心工具）

保留第一轮的“分步任务流”，扩充为：

**第 1 步 场景**
- 城市、天气参考年（来自 `GET /api/operation/options`）。
- 建筑与房间：同类房间数、单间面积、层高、人数、设备散热、朝向、窗墙比、是否每天使用、使用时段（开始/结束）、目标温湿度。提供“从示例开始”的快捷按钮（载入三档或状态变体的 `input`）。
- **空调**：型号（下拉，显示额定制冷量和能效）、每间台数；按钮「帮我算配几台」调用 `POST /api/operation/thermal/size`，显示 1..N 台的达标情况、年用电、缺口小时的小图表，标出“刚好达标的最少台数”，用户可一键采用。
- 屋顶与发电设备：屋顶面积、可用比例；光伏容量「自动比选」或手动输入（多个容量也可）；小风机台数与安装高度。
- 电价：选择电价档案（显示 provisional/“待核验”标记和来源）或固定电价；预算；是否卖电给电网。
- 报价（折叠的“更多条件”）：光伏各项单价、风机各项费用、运维、残值；未填写的报价让对应方案显示“条件不全”，不要自动补默认值冒充报价。
- 碳：排放因子（默认按城市省份，可切换对照）、可选碳价情景（显示来源说明）。
- 储能上限：电池容量档位（只算“最多能挽回多少”，标明不含电池成本）。
- 一句话输入（可选）：保留本地规则解析，只处理使用时段、预算、光伏容量、风机台数/高度、电价、是否外送；房间数、台数、面积等提示“请在表单修改”。

**点击「计算」后**
- 同时发起 `POST /api/operation/hybrid/preview`（典型周，几百毫秒内返回）和 `POST /api/operation/hybrid/jobs`（全年）。
- 先显示 **快速预览**：夏季典型周和冬季典型周的逐小时用电/发电/用上/浪费曲线和该时段合计，醒目标注“预览：典型周物理匹配，不含费用和推荐”。
- 同时显示全年任务的 **真实进度**（来自轮询 `GET /api/operation/hybrid/jobs/{job_id}` 的 `progress`），不做假进度、不做假动画倒计时。
- 全年结果返回后，平滑切换到完整结果，并告诉用户“全年结果已就绪”。
- 出错时把后端返回的中文 `message` 显示在对应 `field` 的表单控件旁，并滚动定位。

**第 2 步 空调用电**：年用电、服务状态（达标 / 有缺口及缺口小时）、逐月柱状图、单房间与项目合计（读后端字段，不在前端相乘）、两本账说明（空调设备购置是另一本账，不与这里相加）。

**第 3 步 比较方案**：决策卡（推荐 + 10 年总花费 + 各方案多花/省下）、四方案卡（状态标签、排除原因）、**容量比选曲线**、能源日历（可选“推荐方案 / 光伏+风机”两组逐时数据：`chart_recommended` 与 `chart`，实时结果用各方案 `hourly`）、电去哪了、典型日曲线、**碳面板**（年减碳、研究期累计减碳、每吨减碳成本、碳价情景开关）、**粗算对照**、**储能上限**（分档或滑块，标明“理想上限，不含电池成本”）。

**第 4 步 决策与导出**：推荐理由（只引用结果中的数值）、适用边界、导出（决策简报可打印 HTML、方案汇总 CSV、逐时 CSV、完整 JSON），保存到“我的方案”。

## 7. 诚实规则（不得违反）

1. “只用电网”在任何结果视图里都显示，并作为基线放在第一位。
2. `unknown`（条件不全，如缺报价）不得显示成“已排除”；`excluded` 要显示后端给出的原因原文；`equivalent` 写明与哪个方案相同。
3. `service_gap` 不得显示成达标；要写缺口小时和“结果不代表同等舒适度下的最优投资”。
4. 费用字段按契约解释：`total_cost_npv_cny` 是 10 年总花费（折现）；`incremental_npv_vs_s0_cny` 负数=比只用电网多花、正数=省下，不得取绝对值丢掉方向；`npv_cny` 不得写成利润。

6. 储能只是理想上限，不含电池成本、寿命、替换，不是储能推荐。

8. 电价档案标为 provisional 的，在使用处显示“待核验”。
9. 用户改任何条件后，旧结果立即置灰并显示“条件已修改，结果已失效”，导出与保存全部禁用，直到重新计算。
10. 导出只从当前显示的结果生成，不为导出再次调用计算。
11. 不用动画伪造计算进度；进度只来自后端 `progress`。
12. 不虚构客户、试点、节能收益、获奖或现场精度；页面边界说明随结果可见：未校准负荷、只计空调、风机未做当地气压温度修正、报价与屋顶需现场确认。
