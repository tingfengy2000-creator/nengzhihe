# 能智核：首轮数据与证据边界

本目录与其他参赛项目独立。所有案例来自公开数据，来源标签与人为扰动说明保留在案例中。

## 文件布局

- `index.json`：工作台公开案例索引，仅开发与演示案例。
- `cases/`：匿名案例，时间戳与各通道数组逐项对齐。
- `private/dev_labels.json`：开发用仿真标签，可用于诊断开发。
- `private/demo_labels.json`：演示标签，不作为留出性能结果。
- `private/holdout_cases/`、`private/holdout_labels.json`：冻结策略后方可交给评测程序的留出数据。
- `holdout_seal.json`：留出案例及标签的 SHA-256；用于核验评测前后内容一致。
- `data_contract.json`：点位、单位、划分、成本与适用范围。
- `raw/`：官方源文件缓存。原始故障文件名仅存在源缓存和私有评测资料，不暴露给诊断策略。

## BDG2：实测回放

选择同一公开站点的两栋教育建筑、一栋办公建筑，使用 2017-05-08 至 2017-06-11 的小时电力记录和站点天气。2017-06-05 以前的四周仅用于计算匹配星期与小时的历史中位数参考，后续一周用于回放。参考曲线不是经过校准的预测区间，不构成节能量或设备故障真值。

三栋建筑仅用于检查可接入、可回放、可解释的工作流程，不构成建筑泛化验证。BDG2 与 LBNL 不做建筑或设备实体关联。

来源：https://github.com/buds-lab/building-data-genome-project-2

引用：Miller et al. (2020), *The Building Data Genome Project 2*, DOI: 10.1038/s41597-020-00712-x。仓库授权为 CC BY-SA 4.0；原文保存在 `raw/bdg2_LICENSE`。

## LBNL SDAHU：有标签仿真

源数据为一个仿真单风道空调机组的分钟记录，统一按五分钟平均重采样，温度由华氏转换为摄氏。文件中的实际年份是 2018。正常、风阀卡滞与盘管阀泄漏的标签由官方文件清单提供。

- 开发：2018-04-02 至 04-05。正常、风阀源文件标称 25%、唯一盘管阀泄漏代表；共 12 个日场景。
- 演示：2018-04-10。正常与“重复记录污染＋设备疑点”；另含一个 BDG2 实测回放。
- 留出：2018-04-16 至 04-22 整周。正常、风阀源文件标称 75%、唯一盘管阀泄漏代表；21 个底层日场景，每个提供原始版本与相同重复记录扰动版本，合计 42 个案例。

全部场景遵守同一日历划分。配对扰动不是独立样本，跨故障同一天共享天气也不是独立建筑。只能报告单一仿真系统、七个留出日块上的首轮结果。

演示日由 04-09 调整为 04-10，是因为开发日 04-02 的风机反馈全天停机，提示仿真控制日历与文档的工作日描述可能不一致。演示需要实际运行工况。留出日期没有据此修改；诊断使用真实风机状态，不以日历强行判定开启。

来源与说明：

- https://fdddata.lbl.gov/data/Simulated_LBNL_FDD_Data_Sets_SDAHU/LBNL_FDD_Data_Sets_SDAHU.zip
- https://fdddata.lbl.gov/data/Simulated_LBNL_FDD_Data_Sets_SDAHU/LBNL_FDD_Data_Sets_SDAHU.pdf
- 许可元数据：https://api.figshare.com/v2/articles/22338283（CC BY 4.0）

引用：Granderson et al., LBNL Fault Detection and Diagnostics Datasets，DOI: 10.25984/1881324。

## 泄漏与源质量审计

官方说明明确使用位置覆盖实现风阀卡滞，使用最小阀位改变实现盘管泄漏。实际位置 `OA_DMPR`、`RA_DMPR`、`CHWC_VLV` 不进入允许证据池；非 Basic 点位的实际转速、风量、功率、占用模式同样统一排除。

文档将 `SA_SP` 与 `SA_SPSPT` 都标为英寸水柱，但开发源值量级约 402 与 1.607，存在单位口径冲突。两点位都排除出定量诊断，不通过自行猜测转换单位来消除冲突。

四个盘管泄漏严重度文件的中央目录 CRC 和长度完全一致。仅保留一个代表，并将私有标签中的可确认严重度设为 null，保留源文件标称值用于审计。完整内容哈希核对见 `private/source_audit.json`；不得将重复严重度算成额外独立样本或声称验证了未见泄漏严重度。

## 人为扰动与修复

统一在 09:00 至 09:55 插入 12 条完全重复记录。该处理不改变原有任何设备点位值。修复是对完全重复的时间记录去重，修复后仍需继续检查运行证据，不能把数据修复等同于设备故障消失。污染来源在每个案例中显式标注为 `human_generated`。

## 成本与成果边界

本轮所有补证均为已有公开档案的数据查询。未执行现场采样，未测量传感器安装费、现场工时或人工运维收益。现场补采成本需要独立估计或实测，不与一次程序查询混为一谈。

未建立真实楼宇设备定位证据、客户试点、合作、实际节能收益或商业成效。本轮首要目标是检验主动查询策略相对固定流程、自适应规则和完整信息版本的真实价值。

## 复现

在项目根目录使用具备 numpy、pandas 的 Python：

```powershell
python scripts/prepare_data.py --download
python scripts/prepare_data.py --prepare --include-holdout
```

`--download` 使用官方地址、范围分块与本地缓存，并保存源文件哈希。诊断调试只读取公开开发数据；冻结策略后，评测程序方可读取 `private/holdout_cases/` 与标签。重建不会把留出案例加入工作台公开索引。
