# APAR 适配边界

专业基线以 NISTIR 6994（2003）第 2.1 节和 Table 2.1 为来源。APAR 本身是按运行模式选择质量/能量关系规则的故障检测方法；原文明确指出规则触发后仍需要额外工作隔离故障来源。因此本轮把“规则触发、设备疑点定位、下一步补证动作”分开计分。

FLEXLAB SZVAV 是单区变风量实验机组。根据数据集设备说明，采样为 1 分钟；温度点为 °F，程序统一转 °C；控制信号为 0—1 的控制指令，不能当作实际阀门位置。占用时段按数据集的 Occupancy Mode Indicator，运行时间轴按真实相邻时间戳，缺失和 `#VALUE!` 保留为缺证。启停和模式稳定窗口由同一套规则提供给 APAR、工作流和消融。

本机组没有返回风机点位，也没有设计最小室外风量/流量点。因此 APAR 的 minimum-OA fraction 规则 2、18 不从混合温度反推，直接标为不可检验；没有用 10—15% 的控制指令冒充流量分数。`fmin=null` 是点位边界，不是阈值优化。

开发只使用 2017-09-11、09-12、09-18、09-20、09-21；正常校准只使用 09-20、09-21。原先规划的 2017-09-14、09-15、09-19、09-22、09-23、09-24 整日留出在早期物理预检中已经被读取，因此响应机制的结果只标为开发与已知留出重检，不能再称未经开发的外部验证。该划分是同一 FLEXLAB AHU 的整日实验分组，不是跨建筑或运营楼宇验证。

APAR 产生的混合风路异常最多支持“需要核查风阀/传感器/风路”的候选。新增响应证据机制只在首个稳定窗口之后获得两个后续、盘管关闭的请求响应窗口时，才把候选提升为“有响应证据的风阀疑点”；没有这种窗口就保留缺证或冲突状态。缺点位、工况不适用、冲突和无充分窗口分别输出，任何未触发规则的情况都不输出“正常”。
