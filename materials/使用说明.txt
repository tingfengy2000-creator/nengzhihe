能智核 首轮参赛材料底稿

当前交付为三份非正式填报底稿和原模板填报生成器，不是可以直接提交的正式Word文件。

一、主要文件
drafts/附件1_项目简表_非正式填报底稿.txt
drafts/附件2_项目说明书_非正式填报底稿.txt
drafts/附件3_项目商业计划书_非正式填报底稿.txt
填报内容.json：同一内容的结构化版本，并记录评测汇总来源与哈希。
字数与要求核对.json：14个限字段落的逐项计数。
渲染状态.json：当前排版核验状态。
references/：用户提供的四份官方原件的哈希一致副本，仅为参考，不是填报成果。
working/：模板结构审计、生成契约及渲染探测日志，不用于正式提交。

二、按真实结果回填
在项目根目录使用具备lxml的bundled Python执行：
python scripts/build_materials.py

生成器只读取output/benchmark.json汇总，不打开封存案例、标签或逐例原始记录。
主要预算固定为预先声明的4；预算2、3只是辅助分析，不根据留出成绩改选主预算。
固定流程、自适应规则、本地模型和完整信息分别保留；没有评测汇总时明确写“待回填”，不填估计成绩。
关键指标表对照本地模型和自适应规则，均为预算4。相对变化由程序计算，负值表示退步；基线为零时不计算相对百分比。错误率没有已回答样本时写为不适用，不填零。
数字进入底稿后再次检查全部限字段落。每个非空白Unicode字符都计1，包含数字、英文、标点和小节标题，因此比常见中文统计更保守。

三、文档生成与渲染门禁
官方Documents渲染脚本在受控PATH下实测报错：LibreOffice soffice.exe was not found on PATH。
当前Windows bundled runtime未包含LibreOffice；没有启动用户桌面LibreOffice、Word或其他办公应用。
不能把OOXML结构正确、文字提取成功或字数通过当作分页排版已通过。

后续需在获得允许的隔离渲染环境后，先渲染并逐页查看三份原模板，再记录working/template_render_receipt.json：
{
  "all_pages_visually_verified": true,
  "templates": [
    {"sha256": "对应原模板SHA256", "page_images": ["实际存在且已逐页检查的绝对PNG路径"]}
  ]
}
templates需要包含三份原件，不能仅凭文件存在便填true。
之后python scripts/build_materials.py --emit-docx会从原模板创建工作副本，保持合并单元格、嵌套指标表、字体、节设置、页脚等结构；仅修改映射的内容、匿名文档属性和打开时更新页码域的设置。
工作DOCX仍输出在working/并标为待渲染，不视作正式提交成果。必须对每份生成文档再次渲染、逐页检查字体、表格分页、溢出、页码与内容，才可交付正式版本。

四、正式提交前仍需完成
1. 核定指南匿名要求与简表姓名、电话、成员栏之间的官方口径；不得自行填造身份。
2. 根据明确判级依据确定TRL，现稿不预选级别，不宣称国内或国际领先。
3. 完成实际评测汇总及创新取舍，确保文档、试验报告、代码版本与日志一致。
4. 原型系统、原创源码、数据与模型许可、复现说明作为软件作品证明材料准备。
5. 全页排版核验及匿名检查，包括文档属性、批注、修订、截图和拟提交源码中的身份信息。
6. 按实际提交系统核对文件格式、大小、命名和截止时间；现有四份文件未给出统一上传扩展名或大小限制，不能补造要求。

五、成果边界
实测BDG2回放、有标签LBNL仿真、人为重复记录扰动分别标注。留出仅来自单一仿真系统、7个日块、21个底层场景的42个配对版本。四份盘管泄漏严重度文件完整内容重复，不能当作独立严重度实验。静压单位冲突点位和注入相关实际位置点位均排除。
本轮没有客户试点、合作、销售、人工效率或实际节能收益证明。材料不填这些不存在的成果。模型主动补证若不能证明实际价值，将收缩创新表述并保留简洁的核验工作流程。
